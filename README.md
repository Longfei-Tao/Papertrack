# PaperTrack

**课题组科研论文投稿协作管理平台（微信小程序）**

让老师快速掌握整个课题组的论文投稿进展，让学生方便管理自己的投稿流程。

- 以**课题组（团队）**为单位组织数据，团队之间完全隔离
- 论文投稿状态 + 中文分类一目了然，支持**状态历史时间线**
- 老师工作台：**最近动态**让导师打开小程序就知道谁的论文有进展
- **返修截止倒计时**，重要节点不错过
- 全简体中文界面，期刊名、论文标题等真实科研信息保留原文

## 功能特性

| 功能 | 说明 |
| --- | --- |
| 首页 / 工作台 | 角色自适应：老师看全组论文与最近动态，学生默认只看自己负责的论文 |
| 论文卡片 | 手机端卡片式展示，状态色条 + 分区 + 负责人 + 更新时间，支持快速扫描 |
| 搜索与筛选 | 按论文/期刊/作者搜索，按状态分类、按成员筛选 |
| 添加 / 编辑 / 删除 | 表单分区（基本信息 / 期刊信息 / 作者信息 / 投稿信息），删除为软删除 |
| 状态历史 | 每次状态变化追加一条记录，绝不覆盖，投稿时间线可视化 |
| 自动更新时间 | 只有数据真实变化才更新 `updatedAt`，无变化保存不产生无效更新 |
| 最近动态 | 状态变化 / 新增 / 删除自动生成团队操作日志 |
| 统计 | 数字卡片 + 状态分布 + 成员论文分布（简洁条形图） |
| 团队 | 邀请码加入 / 创建课题组 / 成员角色管理 / 多课题组切换 |
| 权限 | 管理员 / 成员 / 观察者 三种角色，数据隔离在服务层强制校验 |

## 技术栈

- 微信小程序原生开发（WXML / WXSS / JavaScript / JSON）
- 当前阶段使用 **Mock 本地数据层**（`wx.setStorageSync`），已按 Service 层解耦，可平滑切换云数据库
- 不依赖大型第三方框架

## 快速开始

1. 使用微信开发者工具导入本项目目录。
2. 使用测试号或已配置的 AppID 编译运行。
3. 首次启动自动生成演示数据（两个课题组、14 篇论文），默认以管理员「刘洋」进入「刘洋课题组」。

> 如需清空演示数据：进入「我的」页面 →「重置演示数据」。

## 核心数据模型

```
Team          课题组（inviteCode 邀请码）
├─ TeamMember 成员（role: admin / member / viewer）
└─ Paper      论文（teamId 归属课题组，ownerIds 负责人）
    ├─ PaperStatusHistory  状态历史（追加式，不覆盖）
    └─ Activity            操作日志（供最近动态）
```

- 所有论文必须属于明确的团队，查询在服务层按 `teamId` 强制隔离。
- `visibility` 字段预留「课题组可见 / 仅负责人和管理员可见」。
- 删除采用软删除（`deletedAt`），未来可恢复。

## 角色权限

| 角色 | 权限 |
| --- | --- |
| 管理员（导师 / PI） | 查看与编辑本组全部论文、管理成员、查看统计与最近动态 |
| 成员（学生 / 科研人员） | 查看与编辑自己负责的论文，可查看组内论文 |
| 观察者（预留） | 只读，用于合作老师、访问成员 |
